Fine-tune Qwen on your own JSONL

Harsh Gupta

Two epochs on a JSONL we wrote. The base model invents BERT commands. The adapter writes compute run … --dry-run.

Issue #7 is the guide most people actually want: take a small Qwen, attach LoRA, train on a dataset you wrote. We used Qwen/Qwen3-0.6B, peft + trl SFT, bf16, rank 16. The data is homemade job cards — four lines, always in the same order — so a reader can swap in their own JSONL without changing the trainer.

A dataset you can replace

Each row is {"user", "assistant"}. The assistant is always:

gpu: cheap
timeout_s: 1800
command: compute run train.py::train --gpu cheap --dry-run
note: Dry-run prints the upload plan and spends nothing.

The script generates a few hundred of those on the machine (dry-run, 0.6B, 1.7B, sold-out SKU, lost spot, credits, secrets, OOM). Twenty prompts are held out and never trained. Put your own JSONL in the same shape and you have a different domain.

The base model already speaks four lines. It is still wrong.

Qwen3-0.6B followed the format before any training. It named GPUs and invented commands. “How do I dry-run sft.py::train on a cheap GPU?” came back as sft.py::train --num-iterations 1000. Score: 0/20. Format is not the skill.

A 50-step sample on 120 rows, Vast L4, run run_236bc844e5cda41ee3af6464daa15558, reached 12/20. The full run, two epochs on 414 train / 46 val, run run_18c4da14109e36d7cefc654c7a9d7e05, reached 18/20. Trainable parameters 10.1M of 606M. Train loss 0.584 → eval loss 0.051. About 67 seconds of train-plus-eval on the L4.

The two misses are honest. “First command for train.py::train? Do not spend yet.” still wrote --wait instead of --dry-run. “Qwen3-1.7B LoRA after the 0.6B run already worked.” stayed on gpu: cheap instead of H100. Same format, wrong card.

The token is not on the machine because you stored it

compute secrets set hf writes a secret. train.py::train does not list it, so the job cannot see it. train.py::train_and_push does. This account had no hf secret (compute secrets list was empty), so we did not push the adapter. That is the point of the extra entrypoint, not a missing flag on the sample.

Train it on Compute

One file. Hand compute.cx/SKILL.md to your agent, plus this post’s overlay.

curl -fsSL https://raw.githubusercontent.com/theoriclabs/letsusecompute/main/posts/finetune-qwen-lora/train.py -o train.py
compute run train.py::train --gpu cheap --dry-run
compute gpu list
compute run train.py::train --gpu L4 --timeout 1800 --wait --args '{"sample": true}'
compute run train.py::train --gpu L4 --timeout 3600 --wait

If --gpu cheap quotes a sold-out decorator SKU, pass an available name from the live list. train_and_push is the only entrypoint that injects the HF secret.

No 1.7B run. This issue $0.06. Weights stayed on the artifact; we did not publish them without an HF secret.

What this does not claim

It is not a general assistant. 18/20 is a keyword check on a format we invented. Two prompts still miss. Swap the JSONL if you want a different voice. We did not run 1.7B; 0.6B already changed the answers.
